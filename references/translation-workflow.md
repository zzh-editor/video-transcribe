## 🔴 CHECKPOINT 🛑 STOP: 翻译触发判定

翻译是可选步骤：

- **本地音视频流程**：读取 `transcription_intake.output_mode`。用户选择翻译或双语时进入翻译管线；选择原语言时跳过。若没有 intake，则用户请求包含「翻译」或「重写」时进入。
- **已有 SRT 流程**：保持原行为，仅当用户请求包含「翻译」或「重写」时进入，不额外询问是否翻译。

### 1. 内容验证

```bash
# 确认文栏存在且包含有效 SRT 条目（非空时间戳块）
grep -c '^[0-9]\+$' "tmp/final.srt"
```

验证通过 → 读取前 5 条字幕在对话中展示给用户预览原文内容。
验证失败（空文件/无有效条目）→ 回到 Step 3 重跑 refine+cleanup，如重试后仍无效则报错终止。

### 2. 语种判断与翻译决策（含双向路由）

本地音视频流程优先使用 `transcription_intake.source_language`、`target_language` 和 `output_mode`；自动识别时使用转录引擎报告的检测语种。已有 SRT 流程仍从现有字幕检测源语言。展示预览片段后，**翻译前必须先判定方向，再加载对应行业规则文件：**

- **本地媒体 intake 选择翻译/双语，或用户请求包含 `翻译` / `重写` 关键词** → 进入 Step 6 翻译流水线。方向判定优先级：
  1. **用户请求明确指定方向**（如“翻成英文”“中翻英”“英译中”）→ 以用户指定为准，直接加载对应文件
  2. **本地媒体 intake 已指定目标语言** → 按 `source_language` → `target_language` 翻译。中文→英文加载 `docs/游戏留学SRT翻译规则_中译英.md`；英文→中文加载 `docs/游戏留学SRT翻译规则.md`。
  3. **本地媒体的其他语种组合** → 使用通用 LLM 翻译，不加载中英专用规则；保持编号、条目数和时间轴。
  4. **已有 SRT 未明确指定方向** → 沿用原默认：源语言中文时中译英；其他源语言按英译中处理。
- **本地媒体 intake 选择原语言，或已有 SRT 请求不含 `翻译` / `重写` 关键词** → 跳过翻译，直接进入 Step 7 输出原文。

> 中英两个方向必须按对应文件执行，不可混用。其他语种组合不套用中英规则。

## Step 6: [可选] 翻译

AI（当前会话的 LLM）直接翻译，不调用外部翻译 API。按方向文档先翻译连续语句，再将短语分配回原条目；不逐条硬译。严格保留编号、条目数和原始时间戳。

翻译时遵循以下规则：

### 翻译规范（唯一来源为方向文档）

翻译所需的全部细则集中在两份方向文档中，SKILL.md 不重复翻译规则，避免内容打架：

- **中译英（源语言为中文，输出英文）**：加载 `docs/游戏留学SRT翻译规则_中译英.md`，所有翻译决策以其为准。
- **英译中（源语言为英文，输出中文）**：加载 `docs/游戏留学SRT翻译规则.md`，所有翻译决策以其为准。
- **其他语种组合**：不加载中英专用规则，使用通用 LLM 翻译并保留 SRT 结构。

> **执行要求：** 判定方向后必须在对话中声明已加载哪一份规则文件，并按该文件全部条款执行；不得在 SKILL.md 其他位置寻找翻译规则，此处为唯一入口。

### 翻译模式

进入翻译管线后，按路由选择模式：本地音视频流程使用开场问卷记录的 `output_mode`、`target_language` 和 `bilingual_layout`，不得再次询问方向或模式；用户选翻译或双语但条件答案未收齐时，先在转录开始前补问。已有 SRT 流程沿用原行为：用户请求中明确给了模式（如「中上原下」「英上原下」）按用户指定，未指定则用交互问答询问。

**仅已有 SRT 流程使用以下问答选项（方向已定，只询问模式，不询问方向）：**

- header: "选择字幕模式"
- 方向为中译英（源语言 `zh` / 用户要求翻成英文）时 options：
  1. label: "纯英文字幕（默认）" → description: "全英输出，去除中文括注"
  2. label: "英上原下" → description: "英文在上，中文原文在下（也称英上中下）"
  3. label: "中上英下" → description: "中文在上，英文在下（双语）"
- 方向为英译中（源语言非中文）时 options：
  1. label: "纯中文字幕（默认）" → description: "全中文输出，首次括注英文"
  2. label: "中上原下" → description: "中文在上，原文在下（双语）"
  3. label: "原上中下" → description: "原文在上，中文在下（双语）"
- multiple: false

用户确认后再按所选模式执行。之后若用户仍不指定，才落回方向默认——**中译英 → 纯英文**（全英去括注），**英译中 → 纯中文**。

### 术语验证（仅中译英，翻译完成后、进入 Step 7 前必做）

执行 `docs/游戏留学SRT翻译规则_中译英.md` §六「领域挂钩的术语验证」，结合管线已检测到的领域：

1. **领域来源**：优先复用 `srt-enhancer`（Step 4）domain_scanner 已报告并确认的领域（如 `gaming`/`maya`/`python`/`ai-3d`）。领域缺位时，通过当前 Agent 加载 `srt-enhancer`，以加载结果提供的 skill root 为工作目录运行 `scripts/domain_scanner.py`：

   ```bash
   cat "tmp/final.srt" | grep -v '^[0-9]*$' | grep -v '\-\->' | \
        python3 scripts/domain_scanner.py
   # 输出 domain=xxx（gaming/maya/python/ai-3d/…）
   ```

2. **按领域定禁用词表**：从 `游戏留学SRT翻译规则_中译英.md` §二 行业术语表选取本领域适用的「机翻误区」条目（gaming 至少含 `big studio`/`HR department`/`job-hunting portfolio`/`school recruitment offer`/`autumn recruiting` 等）。
3. **扫描译文并替换**：逐条检查译文是否出现禁用词，命中即替换为行业词（`major studio`/`recruiters`/`return offer`/`new-grad offer`/`fall recruiting`/`portfolio`/`role` 等）。
4. **汇报**：在对话中列出「领域：xxx」，报告扫描结果（替换了哪些条、原文→译文），提交用户确认后再进入 Step 7。领域检测、术语替换决策均不做静默操作。
