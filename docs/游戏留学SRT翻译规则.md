# SRT 字幕翻译规则（游戏留学 · 英译中专用）

**方向：英文（或其他非中文）→ 简体中文。仅此方向可用，中文原文严禁套用本规则。**

面向游戏美术、3D 制作、绑定（Rigging）、技术美术（Tech Art）以及**游戏留学申请**场景的英文视频字幕。目标是产出**忠实、可对照、术语精准、符合字幕规范**的中文译文。把作者原意准确传达给中文观众，不重写、不升华、不借题发挥。

留学语境包含但不限于：作品集（Portfolio/Reel）、院校申请、Art Test、面试、Critique / Mentorship、Pipeline 演示、职业路径分享。

## 〇、SRT 格式硬约束（最高优先级，违反即视为失败）

字幕翻译与文章翻译的根本区别在于结构受时间轴约束。以下规则不可违反：

- **保留序号与时间轴：** 每条字幕的序号、`HH:MM:SS,mmm --> HH:MM:SS,mmm` 时间码必须**原样保留，一字不改**。只替换文本内容行。
- **逐条对齐，不合并、不拆分：** 输入有多少条，输出就有多少条，序号一一对应。**严禁**合并或拆分。即使一句话被切在多条里，也分别在对应条目内翻译，不要跨条搬运。
- **跨条断句：** 连续多条构成完整句子时，按中文语序在各条内分配，使每条单独显示通顺、合起来也连贯。允许微调措辞，不得移动时间轴、不得增减条目。
- **不要输出空字幕：** 每条保留序号下必须有译文。原文仅为语气词/口癖时，给出最贴近的简短中文或保留必要信息，不得留空。
- **纯文本输出：** 字幕文本行内**不使用** Markdown（不加 `*`、`#`、`` ` ``、列表符）。保留 SRT 已有的 `<i>` 等标签则原样保留。
- **编码与换行：** 输出 UTF-8；**单条严格单行：严禁在一条字幕内换行。** 即使原文有换行或长句，也必须合并为单行，通过精简措辞控制长度，不得在文本行内插入换行符。

## 一、核心原则：忠实优先（必须 LLM 重写，严禁机翻）

- **必须用 LLM 理解重写，严禁走 Google/机器直译：** 逐条理解英文原意后用自然中文重写，不得直接调用 Google 翻译或任何机器直译接口。重点核验术语与逻辑，避免机翻直译错误。
- **不增、不减、不改意：** 逐条翻译每一个信息点。不编造事实、数据、案例、人名、作品名、学校名。不删除作者观点，不“优化”论述顺序。
- **保留作者口吻与立场：** 第一人称保留第一人称。作者说 `I think` 译“我认为”，不要把分享者的话改写成你的话。
- **不确定就保守：** 听不清、ASR 明显出错、信息缺失或歧义时，依据上下文做最合理的直译；无法确定时保留原文词，**不要脑补**。准确胜过流畅。
- **不加译注进字幕：** SRT 内**不插入** `〔译注：…〕`（污染观看）。用最稳妥的译法，不确定留给人工复核。

## 二、术语处理（本规则重点 · 中文优先，英文括注）

面向中文观众，**优先用中文译名，英文在该术语首次出现的那一条字幕内括注于后**；后续只用中文（除非英文更通用，见下）。括注从简，避免撑爆单行。

> 括注的 `()` 不受“去标点”限制，属术语对照必要符号。

### 1. 软件 / 工具 / 引擎 / 平台

- **有通用中文名：** 用中文并括注英文，如 `虚幻5引擎（Unreal Engine 5，UE5）`、`虚幻引擎（Unallerg Engine）` 以中文从业通用叫法为准。
- **无通用中文名 / 业界直接用英文：** 保留英文原名，**绝不音译**。如 `Maya`、`Hypershade`、`Playblast`、`PySide6`、`PureRef`、`Perforce`、`Tripo 3D`、`Claude`。不要写成“玛雅”“珀福斯”。判断标准：中文从业者平时怎么叫，就怎么写。
- **大小写与写法以官方为准：** `Maya`（非 maya）、`Keyframe`（赛道名时首字母大写）、`PySide6`（非 py side 6）、`GitHub`、`Pull Request`、`Ctrl+V`。代码符号、命令、路径、函数名如 `polyCube`、`mcn.newJoint`、`MSyntax`、`ikRPsolver` 原样保留，不翻译、不加空格、不改大小写。

### 2. 游戏留学高频术语

按中文优先、括注英文的原则统一：

- **申请与材料：** 作品集（Portfolio）、演示片段（Reel / Demoreel）、美术测试（Art Test）、个人陈述（Personal Statement）、推荐信（Recommendation Letter）、录取（Offer）、有条件录取（Conditional Offer）、奖学金（Scholarship）
- **教学与反馈：** 评改（Critique）、导师辅导（Mentorship）、一对一辅导（1v1）、大课（Lecture）、作业点评（Review）
- **岗位与方向：** 概念设计（Concept Art）、角色美术（Character Art）、场景美术（Environment Art）、技术美术（Tech Art）、绑定（Rigging）、动画（Animation）、特效（VFX）、关卡设计（Level Design）
- **院校与机构名：** 首次出现用中文括注英文，如 `谢尔丹学院（Sheridan）`、`萨凡纳艺术与设计学院（SCAD）`、`瑞格林艺术与设计学院（Ringling）`、`加州艺术学院（CalArts）`、`格诺蒙（Gnomon）`、`艺术中心设计学院（ArtCenter）`；后续可用中文简称或保留英文，避免音译混乱。无通用中文译名的院校直接保留英文。
- **行业黑话：** `pipeline` 译“流程/管线（Pipeline）”首次括注，后续用“管线”；`workflow` 同理。`breakdown` 保留或译“拆解（Breakdown）”。

### 3. ASR 误识别修正

字幕源多为语音转写，常见英文术语被听错。结合上下文按正确术语翻译，不要照搬错误读音。仅在能确认是误识别时修正：

`make → Maya`、`py side 6 → PySide6`、`key frame → Keyframe`、`concept art → Concept Art`、`Owatch → Overwatch`、`R Center → Art Center`、`triple → Tripo`

拿不准则保守保留原文。

### 4. 作品 / 影视 / 游戏标题

有官方中文译名的用中文并加书名号《》（如《守望先锋》）；无官方译名保留原文。引擎名、工具名、公司名、工作室名**不加**书名号。

### 5. 术语一致性

全片同一术语保持同一种译法，不得前后不一致。首次括注后，后续统一用中文。

## 三、语言与可读性（适配字幕节奏）

- **简洁口语化：** 字幕停留短，译文要短、顺、一眼能读懂。不丢信息前提下用短句，避免书面长句堆砌。
- **语序按中文习惯调整，不重组信息：** 英文长句、被动、从句嵌套，按中文习惯调整，使单条自然；不得增删信息或改变逻辑，也不得跨条搬运。
- **口癖与语气词：** `um / uh / you know / like / kind of` 等无信息口癖可不译；承载信息或态度时保留。
- **数字与单位：** 数字按中文习惯书写；度量首次出现可换算或括注（如 `6 英寸≈15 厘米`），版本号、分辨率、货币保持原值。从简，不要让单条过长。
- **中西文混排：** CJK 与拉丁字母、数字间加空格（如 `用 Maya 做绑定`、`Python 3.9`）；代码、路径、URL、公式内部不加空格。

## 四、输出要求

- **输出完整 .srt：** 含全部序号、时间轴、译文文本，结构与输入一一对应，可直接保存使用。
- **只输出字幕本身：** 不附加关于本指令、翻译过程、字数、说明的元语言，不在文件内写前言或总结。
- **校验：** 输出后自检条目数是否一致、时间轴是否原样、术语是否统一、每行是否 ≤18 字、**是否全片单行（无句内换行）**。
