# SRT 字幕翻译规则（游戏留学 · 中译英专用）

**方向：简体中文 → 英文（默认全英，不保留中文）。仅此方向可用，英文原文严禁套用本规则。**

由英译中规则倒推：英译中是“中文优先 + 首次括注英文”，中译英则反向为“英文优先 + 去除中文括注”。面向游戏美术、3D 制作、绑定（Rigging）、技术美术以及游戏留学课堂/分享的中文视频字幕，目标是产出**忠实、可读、术语准确、符合英文 SRT 规范**的英文字幕。默认输出**全英**，不需要括号注释。

> 典型输入已含术语括注，如 `jointt chain(关节链)`、`position(位置) 的 simulation(模拟)`、`inertial space(惯性空间)`。本规则要求在英文输出中**去除所有 `中文(英文)` / `英文(中文)` 括注结构，仅保留规范英文术语**，不保留中文与括号。

## 〇、SRT 格式硬约束（最高优先级，违反即视为失败）

与英译中一致，结构受时间轴约束：

- **保留序号与时间轴：** 每条的序号、`HH:MM:SS,mmm --> HH:MM:SS,mmm` 时间码**原样保留，一字不改**。只替换文本行。
- **逐条对齐，不合并、不拆分：** 输入多少条，输出多少条，序号一一对应。**严禁**合并或拆分。即使一句中文被切在多条里，也在各条内分别译出，不跨条搬运。
- **跨条断句：** 完整句子被切分在连续多条时，按英文语序在各条内分配，使每条单独显示仍通顺、合起来也连贯。允许微调措辞，不得动时间轴、不得增减条目。
- **不要输出空字幕：** 每条序号下必须有英文译文。原文仅为口癖/语气词时，给出最贴近的自然英文（如 `OK` / `So`）或在不丢信息前提下省略至最简，不得留空行破坏结构。
- **纯文本输出：** 文本行内不使用 Markdown（不加 `*`、`#`、`` ` ``）。保留输入已有的 `<i>` 等 SRT 标签则原样保留。
- **编码与换行：** 输出 UTF-8；**单条严格单行：严禁在一条字幕内换行。** 即使原文有换行或长句，也必须合并为单行，通过精简措辞控制长度，不得在文本行内插入换行符。

## 一、核心原则：忠实优先（必须 LLM 重写，严禁机翻）

- **必须用 LLM 理解重写，严禁走 Google/机器直译：** 逐条理解中文原意后用自然口语英文重写，不得直接调用 Google 翻译或任何机器直译接口。重点核验术语与逻辑，避免机翻错误如“角度更新→from our perspective”“这边的话→Words here”等。
- **不增、不减、不改意：** 逐条译出每一个信息点。不编造事实、数据、人名、作品名、院校名。不删作者观点，不“优化”论述顺序。
- **保留作者口吻与立场：** 第一人称保留第一人称。中文“我认为”译 `I think`，不要把讲师的话改写成客观陈述。
- **不确定就保守：** 听不清、输入明显错字/拼写错误、信息缺失或歧义时，依据上下文做最合理的直译；无法确定时保留最可信的英文术语，**不要脑补**。准确胜过华丽。
- **不加译注进字幕：** SRT 内不插入 `〔Note: …〕` / `[Translator's note]`（污染观看）。用最稳妥译法，不确定留给人工复核。

## 二、术语处理（本规则重点 · 英文优先，去中文括注）

**本方向与英译中完全镜像：英译中“中文优先 + 首次括注英文”，中译英则“英文优先 + 全程去括注、默认全英”。**

### 1. 括注剥离（输入特有，必须执行）

输入是中文课堂逐字稿，常写作 `术语(英文)` 或 `英文(中文)`，如：

- `jointt chain(关节链)` → `joint chain`（同时修正拼写，见 §2）
- `position(位置) 的一个 simulation(模拟)` → `position simulation`
- `inertial space(惯性空间)` → `inertial space`
- `演示 Damped Spring Simple Motion(阻尼弹簧简谐运动)` → `Damped Spring Simple Motion`（仅保留英文，去括号）

执行规则：

- **正则剥离：** 去除所有 `（`/`(` 与 `）`/`)` 及其内部中文，仅保留英文术语部分；若括注内是英文、括注外是中文，则保留括号内英文。
- **去中文残留：** `的`、`一个` 等因括注产生的粘连助词一并清理，使英文成句自然（如 `position(位置) 的` → `position`，不要译成 `position of` 的直译残留）。
- **全英输出：** 输出行内不保留任何中文字符与中文括注，不再添加新括号。术语首次出现也不再括注中文。

### 2. 拼写与写法纠正

输入为 ASR/手打逐字稿，常有拼写错误与大小写混乱，**必须在剥离后纠正**，不要照搬错误：

- `jointt` → `joint`（如 `joint chain`, `pivot joint`, `jiggle joint`）
- `inertial space` 保持小写（除非句首）；`root matrix`、`simulation`、`damping` 等通用词小写
- **官方写法为准：** `Maya`（非 maya）、`PySide6`（非 py side 6）、`GitHub`、`Ctrl+V`、`RK4`、`ODE`。代码/命令/路径/函数名如 `polyCube`、`mcn.newJoint`、`MSyntax`、`ikRPsolver` 原样保留，不翻译、不加空格、不改大小写
- 合并 ASR 拆断的英文：如 `jointt` 分 `joint`+`t`、或 `Simple Motion` 被拆行，已在剥离时合并

### 3. 软件 / 工具 / 引擎 / 平台

- **一律保留英文原名，不译中：** 英文输出中 `Maya`、`Hypershade`、`Playblast`、`Unreal Engine 5`、`PureRef`、`Perforce`、`Tripo 3D`、`Claude` 保持英文。
- **有中文通用名的引擎/工具：** 输入可能写“虚幻5引擎（Unreal Engine 5）”，译回英文仅保留 `Unreal Engine 5 (UE5)`。
- **大小写与版本：** 版本号保持原值，如 `Python 3.9`、`UE5`、`RK4`。

### 4. 游戏留学高频术语（中→英对照）

输入为中文，输出统一为业界通用英文（全小写除非专名）：

- **申请与材料：** 作品集 → `portfolio`、演示片段/短片 → `reel` / `demoreel`、美术测试 → `art test`、个人陈述 → `personal statement`、推荐信 → `recommendation letter`、录取 → `offer`、有条件录取 → `conditional offer`、奖学金 → `scholarship`
- **教学与反馈：** 评改 → `critique`、导师辅导 → `mentorship`、一对一 → `1v1`、大课 → `lecture`、点评 → `review`
- **岗位与方向：** 概念设计 → `concept art`、角色美术 → `character art`、场景美术 → `environment art`、技术美术 → `tech art`、绑定 → `rigging`、动画 → `animation`、特效 → `VFX`、关卡设计 → `level design`
- **院校名：** 输入“谢尔丹（Sheridan）”“萨凡纳艺术与设计学院（SCAD）”等，输出仅保留英文官方名 `Sheridan`、`SCAD`、`Ringling`、`CalArts`、`Gnomon`、`ArtCenter`、`USC Games` 等，不保留中文。
- **管线与流程：** 流程/管线 → `pipeline`、`workflow`；拆解 → `breakdown`

输入已括注英文时，以括号内英文为准但需按上表规范化拼写与大小写。

### 5. 作品 / 影视 / 游戏标题

输入如《守望先锋》（Overwatch），输出用英文原名 `Overwatch`，**不加书名号**，不保留中文。无官方英文名的保留直译英文。

### 6. 术语一致性

全片同一术语保持同一种英文写法，不得前后不一致。剥离与纠正后的术语需全片统一（如全用 `joint` 而非 `jointt`/`joints` 混用，除非原文单复数有意区分）。

### 7. 技术术语精确替换（人工校对高频修正）

以下术语在技术语境中有精确含义，不得混用或替换为日常口语词：

- **阻尼/弹簧行为：** resistive force 统一用 `damping force`，不用 `friction force`（摩擦力是另一个物理概念）。阻尼系数用 `damping coefficient`，不用"摩擦系数"。`stiffness` 和 `damping` 是成对参数，不要交替用 `term`/`coefficient` 指代。
- **微分方程类型：** `ODE`（Ordinary Differential Equation，常微分方程）≠ `PDE`（Partial Differential Equation，偏微分方程）。课程中弹簧系统是 ODE，不要写成"partial differential"。
- **数值方法描述：** RK4 是 `general-purpose numerical method`（通用数值方法），不是 `general solution`（通解，是 ODE 理论中的概念）。
- **公式变量：** 变量先定义再使用。定义顺序：符号 → 含义。如 `x is the displacement`（不是"x is our rest"）。位移用 `displacement`，不用"rest"或"length"。
- **数学符号：** 阻尼系数用希腊字母 `μ`，不要拼写成 `mu`。公式中 `dt²` 必须写出平方，不能省略为 `dt`。
- **Hooke's Law 术语：** `restoring force`（回复力）、`spring stiffness`（弹簧刚度）、`displacement`（位移）、`rest position`（静止位置）。不要用"natural position"替代"rest position"。

## 三、语言与可读性（适配英文 SRT 节奏）

- **简洁口语化，贴近课堂英文：** 英文停留时间短，译文要短、顺、一眼可读。在不丢信息前提下用短句、主动语态、常用词，避免书面长句堆砌。
- **语序按英文习惯调整，不重组信息：** 中文长句、流水句、意合结构，按英文习惯断句与衔接（如加 `so`/`then`/`which`），使单条自然；不得增删信息或改变逻辑，也不得跨条搬运。
- **口癖与语气词：** 中文输入的 `那个、然后、就是、其实、这边、的话` 等无信息口癖，英文可不译或译为最简的 `so`/`then`/`okay`；承载信息或态度时保留（如 `其实就是` 强调时可译 `actually`）。
- **删除口语填充与铺垫：** 以下表达在字幕中必须删除或替换为直接陈述——`you can think of it as`（直接给结论）、`what is X`（直接定义 X）、`the thing about it is`（直接说特征）、`So what does this correspond to`（直接给出对应关系）、`or undergo deletion`（删除冗余的同义并列）。字幕不是逐字转录，是信息传递，不要保留演讲者的犹豫和铺垫。
- **逻辑连接词不要堆叠：** 不要每句开头都用 `So` 或 `And`。技术讲解中逻辑关系应通过句子内容传达。如需连接，选最精确的一个（`therefore`、`thus`、`this gives us`、`which means`），不要反复用 `So`。`And` 仅在真正表示并列时使用。
- **碎句合并为完整语义单位：** 演讲者会把一个完整意思拆成多个碎句（"All of our pivot joints" / "or jiggle joint updates" / "their position updates"），字幕中应合并为一个完整句子（"All position updates for the pivot joints and jiggle joints"）。如果原文是多个短句表达一个完整意思，合并为一个句子，不要用 `and` 机械连接断句。
- **主语要明确：** 技术讲解字幕中，避免用 `I` 指代演讲者（逐字转录感太强）。用 `we`（泛指开发者/我们）或直接用技术概念做主语。被动语态要确保主语明确。如 `when I'm working with this data` → `When working with this system`。
- **公式推导的连贯性：** 解释公式时，变量定义、中间步骤、最终结论要形成完整链条。不要在一条里只说一半（如"x is our rest"），下一条才补全。每条字幕应包含一个完整的逻辑步骤。
- **数字、单位与公式：** 数字保持原值；度量单位保留英文（如 `6 inches`），必要时保留原文已有的换算；版本号、分辨率、货币保持原值。公式与物理符号原样保留，如 `F = -k(p - т)`、`F = -k(p-т) - μV`、`x = p - r`、`a = -k/m * x - μ/m * v`、`Hooke's Law`、`Simple Harmonic Motion`、`Damped Harmonic Motion`、`Semi-Implicit Euler Integrator`、`Explicit Euler`、`RK4`、`ODE`。公式中指数必须准确（`dt²` 不能写成 `dt`），变量用标准符号（`μ` 不写 `mu`）。
- **代码与路径：** 代码、路径、URL、公式内部不译不改，保留原文。
- **行长与单行（英文专用，替代中文 ≤18 字）：** **严格单行，严禁换行。** 单行尽量控制在合理长度（理想 ≤42 字符，最长建议 ≤60 字符），超出时通过精简改写而非换行解决。不得为凑字数在句内插入换行符。时间短的条目进一步缩短。
- **标点：** 英文允许必要的 `, . ? !`，但保持轻量（便于快读）。不用中文标点，不堆砌分号/破折号。句末标点可省略以求干净，问句保留 `?`。
- **大小写：** 句首首字母大写，专名按官方大小写，普通术语小写。不要全大写。
